01 — What is open source

Software you can read,
modify & share.

Open source software is code that anyone can view, use, change, and distribute. When a project is open source, it means the source code — the actual instructions that make the software work — is freely available for inspection and collaboration.

This is the opposite of proprietary software, where the code is kept secret and users can only interact with a finished product. Open source flips that model: the community is invited in.

When you contribute to open source, you're joining a tradition that built the internet. Git, Linux, Firefox, Python, TensorFlow, React — all open source, all shaped by thousands of contributors who never needed anyone's permission to get started.

👁

Transparency

Anyone can read the code and understand exactly how it works — no black boxes.

✏️

Modification

You can fork a project, fix it, improve it, and adapt it to your own needs.

🔁

Distribution

Share your changes, publish your fork, let others build on what you built.

🤝

Community

Collaborate with people across the world around shared code and shared goals.

02 — How it works

The lifecycle of
a contribution

01

Find a Project

Browse GitHub, GitLab, or find an issue in software you already use. Look for "good first issue" labels.

02

Fork the Repo

Create your own copy of the repository under your account — your sandbox to experiment freely.

03

Make Changes

Clone it locally, create a new branch, write your fix or feature. Commit early and often.

04

Open a PR

A Pull Request proposes your changes to the original project. Explain what you did and why.

05

Get Reviewed

Maintainers and community members review, discuss, and help improve your work before merging.

03 — Key concepts

The vocabulary you
need to get started

Version Control

Repository (Repo)

A folder that contains all the code, history, and metadata for a project. The source of truth for a codebase.

github.com/org/project-name
Branching

Branch

A parallel version of the code where you can make changes safely, without affecting the main codebase until you're ready.

git checkout -b feature/my-change
Collaboration

Fork

Your personal copy of someone else's repository. You can freely experiment and then propose merging back.

gh repo fork org/project
Proposing Changes

Pull Request (PR)

A formal request to merge your changes into the main project. The centerpiece of open source collaboration.

gh pr create --title "fix: ..."
Review Process

Code Review

Maintainers and contributors review changes, leave comments, and request adjustments before code is accepted.

gh pr review --comment
Licensing

Open Source License

Legal terms defining how you can use, modify, and distribute the code. MIT, Apache, GPL are common examples.

cat LICENSE
04 — First contribution

Your first PR,
step by step

✓

Set up Git & GitHub

Install Git, create a GitHub account, and configure your name and email locally.

✓

Find a "good first issue"

Search GitHub for label:good-first-issue in any language you know.

✓

Fork, clone, and branch

Fork the repo to your account, clone it locally, create a branch named after your change.

✓

Read CONTRIBUTING.md

Most projects have a guide explaining coding style, commit format, and how to run tests.

✓

Make your change & commit

Small focused changes are best. One fix per PR. Write a clear commit message.

✓

Open a PR with context

Describe what you changed, why, and reference the issue number. Be kind — you're a guest.
